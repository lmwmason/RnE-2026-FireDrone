1. FireDrone (20초)
안녕하세요. 저희는 로봇팔을 탑재한 소방 드론 FireDrone을 연구하고 있습니다. 건물과 주거 화재에 대응하는 것이 최종 목표입니다. 오늘은 현재 만든 하드웨어 설계와 비행 제어, 시뮬레이션 결과를 소개하고, 실제 기체로 옮기기 전에 필요한 검증 방향을 자문받고자 합니다.

2. 연구 목표와 현재 개발 범위 (25초)
핵심 질문은 로봇팔의 움직임이나 고장이 비행 자세를 흔들 때, 제어기가 얼마나 안정적으로 대응할 수 있느냐입니다. 저장소에는 전원 회로와 비행 제어 보드 설계, STM32 제어 코드, 두 종류의 시뮬레이션 환경이 있습니다. 반면 AI 판단과 소화 장치를 포함한 전체 임무 통합은 앞으로 진행해야 합니다. 따라서 이번 컨설팅의 중심은 비행 기반 기술입니다.

3. 하드웨어 설계 (30초)
하드웨어는 장치별 전원 공급과 비행 제어 보드로 나누어 설계하고 있습니다. 왼쪽은 BEC 보드의 실제 PCB 설계 이미지이고, 오른쪽은 배터리 전원을 여러 전압으로 분배하는 회로도입니다. STM32에는 3.3볼트, Raspberry Pi와 Arduino에는 5볼트, 구동 장치에는 12볼트를 공급하도록 설계했습니다. 회로가 있다는 것과 전기적 성능이 검증됐다는 것은 다르므로, 부하 전류와 발열, 센서에 전달되는 전원 노이즈를 우선 확인하려 합니다.

4. 비행 제어 구조 (35초)
비행 제어는 센서에서 시작해 모터 출력으로 끝납니다. 먼저 UKF가 센서의 잡음을 고려해 자세와 각속도를 추정합니다. ADRC는 예상하지 못한 외란을 추정하고, MRAC는 모델 변화에 대응하는 보정 역할을 맡습니다. INDI는 현재 움직임과 목표의 차이로 필요한 모터 출력 변화량을 계산합니다. 마지막 CAM은 고장 난 모터와 출력 한계를 고려해 명령을 배분합니다. 현재 제어 주기는 1밀리초입니다. 다만 알고리즘이 연결됐다는 사실과 실제 비행에서 충분한 성능을 보장한다는 것은 구분해 검증하고 있습니다.

5. 로봇팔 외란 시험 (30초)
로봇팔을 움직이면 기체에도 반작용 토크가 생깁니다. 화면은 기존 X4 시험의 실제 로그를 재생한 것으로, 팔 외란이 있을 때 기체의 궤적과 자세, 모터 출력을 함께 볼 수 있습니다. 현재 X8 시뮬레이터에서는 단일 링크 팔의 각도와 가속도에 따른 반작용을 계산합니다. 하지만 실제 팔과 기체의 완전한 결합 운동까지 재현한 것은 아닙니다. 팔의 질량과 길이, 구동 속도를 실측해서 모델을 보정하는 것이 다음 과제입니다.

6. X4 수정 전후 비교 (40초)
시뮬레이션은 제어 코드의 오류를 찾는 데 활용했습니다. 이번 자료를 위해 같은 정상 비행 조건에서 수정 전과 수정 후의 X4 프로그램을 각각 다시 실행했습니다. 회색 선은 수정 전으로, 이륙 후 고도를 잃고 추락했습니다. 검은 선은 수정 후로, 약 35초에 임무를 마치고 착륙했습니다. 수정 내용에는 외란 추정기의 잘못된 입력 연결, UKF의 수치 안정성, 실제 모터 지연을 무시하던 부분이 포함됩니다. 이 비교는 각 한 번의 시뮬레이션 결과입니다. 기존 로그에는 복합 고장 시험의 실패도 남아 있어, 모든 환경에서 안정적이라고 결론내리지는 않았습니다.

7. X8 시뮬레이터 (35초)
현재 개발의 중심은 네 개의 팔에 모터를 위아래로 배치한 동축 X8입니다. 화면은 이번에 직접 실행한 최신 대시보드입니다. USB 조종기의 스틱으로 목표 기울기와 추력을 주고, 자세와 고도, 팔의 움직임, 여덟 모터 출력을 확인하도록 만들었습니다. 지금 캡처는 조종기를 연결하지 않은 시동 해제 상태입니다. 자동 경로 비행 화면은 아닙니다. 모터 할당과 물리 모델, 고장 주입 관련 코드 테스트는 통과했지만, 실제 조종기 연결과 실제 기체 비행은 별도 검증이 필요합니다.

8. 인지와 모델링 통합 (25초)
프로젝트에는 비행 제어 외의 확장 요소도 있습니다. 왼쪽은 저장된 Simulink 모델의 미리보기로, 센서와 제어기, 기체 동역학을 연결한 구조입니다. AirSim 코드는 LiDAR 점군을 받아 2차원으로 표시하는 단계입니다. 폴더 이름에 장애물 회피가 들어 있지만 현재 코드를 자율 회피 구현으로 소개하지는 않습니다. 앞으로 인지 결과를 비행 명령에 연결하고, AI 화재 판단과 소화 장치까지 통합해야 합니다.

9. 실기 검증 과제 (30초)
다음 단계는 가정값을 실측값으로 바꾸는 것입니다. 질량과 관성, 모터의 추력 곡선과 응답 지연, 동축 프로펠러의 간섭을 측정해야 합니다. 왼쪽은 저장소에 있는 외부 시험 지그 참고 자료이며 저희가 제작한 실물 사진은 아닙니다. 이런 제한된 시험 환경을 활용해 팔의 반작용과 고장 대응부터 확인하려 합니다. H7도 현재는 제어 라이브러리 단계여서, 센서와 ESC 드라이버를 연결한 후 실제 보드에서 제어 주기를 만족하는지 측정해야 합니다.

10. 컨설팅 요청 (30초)
오늘 네 가지에 대해 자문을 부탁드리고 싶습니다. 첫째, 현재 X8과 10인치 프로펠러 계획에서 목표 중량과 추력 여유를 어떻게 정할지입니다. 둘째, 여러 제어 알고리즘을 함께 사용하는 현재 구조를 유지할지, 검증하기 쉬운 구조로 단순화할지입니다. 셋째, 고장 시험의 우선순위와 합격 기준을 어떻게 설정할지입니다. 마지막으로 H7 이식, 팔 보상, 인지 통합 중 어떤 순서가 적절할지 조언을 듣고 싶습니다. 컨설팅을 통해 실측과 비행 검증 계획을 구체화하겠습니다. 감사합니다.

총 계획 시간: 300초 (5분)
